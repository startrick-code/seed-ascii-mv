# 音乐同步样片测试记录

基于 214.360816 秒本地 MP3；原曲未复制到项目。本次未修改任何远程仓库或线上部署。

## 已执行并通过

- 全部 JS 语法检查。
- `node tests/music.cjs`：三种网格共 2703 个完整时间采样；四个新边界的前/中/后；非空帧；无非有限透明度；匹配音轨包络的跳转确定性。
- 独立几何响应检查：在 7/15/23/27 秒相同时间，零/满频段输入导致字符内容或位置分别约 1014/1622/532/198 格差异。比较不使用亮度或透明度，证明不是仅有亮度变化；极值测试不等于真实曲目各时刻都有同等变化。
- `tests/music-browser.py` 在实际 Chromium 运行：先播放原创测试音轨，再通过文件选择器加载实际 MP3；SHA 匹配、真实 FFT 中频非零、暂停像素及时间保持、直接跳转和往返 seek 像素一致、20.773 秒章节、响应开关改变画面、沉浸切换、三种视口无横向溢出、拖动后恢复、30 秒停止、无 JS 异常。
- docs/music-*.png 是 Chromium 加载实际 MP3 后暂停/跳转的真实截图，非模拟图，不含音频。

`tests/music-continuous.py` 实际 MP3 不跳转完整播放30秒通过：2 / 6.3 / 15 / 21.3 / 28 / 30秒六次采样的动画时钟与音频时间差最大约0.012秒，结尾正确停止。该检查比较软件主时钟与 DOM 中动画时间，不是麦克风实测音响延迟。单文件版本也通过原创测试音轨实际播放验证。

## iPad 真机步骤

1. 在独立测试地址打开本版本，横屏选本地 MP3，等待“已识别校准音轨”，点击播放。不要覆盖线上旧版测试。
2. 0–5.8 秒为初始化，5.887 秒应明显释放曲线；20.773 秒应出现大型波前并进入网络。
3. 每幕暂停 3 秒；画面和时钟应停止。暂停直接跳到 6.3、15、21.3、28 秒，画面应立即对应，往返数次不依赖播放历史。
4. 播放中拖动后恢复，暂停中拖动后保持暂停；测试章节、±5 秒、重播及正负偏移。
5. 关闭响应对比几何，再开回；换成别的本地音频应显示“其他音频”，不会错误套用校准包络。测试音轨也不套用原曲包络。
6. 切网格与 24FPS；观察保持动作真实时长。沉浸、折叠设置和横竖屏往返，画面完整、无横向溢出。
7. 完整播放 30 秒，确认末尾停止；测试切后台、恢复以及 Safari 音频中断处理。记录机型、系统、画质、实际帧率及声画感受。

## 复现

在项目目录启动 `python3 -m http.server 8094`。运行 `node tests/music.cjs`；设置环境变量 TEST_AUDIO 指向本机 MP3 后，执行 `python3 tests/music-browser.py` 和 `python3 tests/music-continuous.py`。不将 MP3 放在静态服务目录内。
